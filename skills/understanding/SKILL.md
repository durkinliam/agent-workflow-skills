---
name: understanding
description: Reach a shared understanding of an idea, plan, or task with the user. Use when the user is talking through an idea, task, or plan, or when the desired outcome isn't yet clear enough to act on.
---

Start by inspecting the project and any other sources needed to establish facts. Separate understanding the current state, which is investigated, from deciding the future design, which is agreed with the user. Use the questioning skill when asking the user anything.

The understanding should be broken down into a design tree, where it is split into branches and answers hang off each branch. Branches can depend on each other; after each answer, work out which branches can now be answered. Each branch is resolved, explicitly deferred, or blocking.

Treat the design tree as a working model. Reuse established answers rather than asking again, but when new evidence or a user answer changes an earlier decision, revisit that decision and the conclusions that depend on it. Explain the resulting change in understanding and preserve unaffected decisions.

A shared understanding has been reached when no unresolved branch would materially change the next agreed step. Report it back to the user: the desired outcome and why it matters, what observable success looks like, constraints, exclusions, deferred decisions and remaining uncertainties.
